## Запуск

Примеры — workspace репозитория [`evgkch/machjs`](https://github.com/evgkch/machjs), и все они собраны в один проект Vite: индексная страница лежит в корне, каждый пример — по своему пути. Из корня репозитория:

```sh
npm ci
npm run dev:examples   # собирает библиотеку и виджеты, затем http://localhost:5173
```

Из этого каталога, когда библиотека и пакет инспектора уже собраны:

```sh
npm run dev       # http://localhost:5173
npm run build     # tsc --noEmit + сборка в dist/
npm run preview   # посмотреть собранное
npm test          # каждая страница в DOM: машина прогоняется, виджеты сверяются
```

Библиотека и виджеты берутся из workspace, а не из npm: изменение в `packages/core` или `packages/inspector` попадает в примеры после пересборки этого пакета.

## Оболочка

Три файла в корне общие для всех страниц примеров:

| Файл                       | Что в нём                                                                        |
| -------------------------- | -------------------------------------------------------------------------------- |
| [`page.css`](page.css)     | Сплошной текст и два свойства, о которых у токенов нет мнения                     |
| [`shell.css`](shell.css)   | Полноэкранный каркас: строка, сцена, док, палуба — и раскраска инструмента        |
| [`shell.ts`](shell.ts)     | `dockEdge` — переключатель, который переносит панели с края вниз и обратно        |

Пример пишет `@import "../../shell.css";`, затем `@layer subject { … }` и оформляет то, что стоит на сцене. Обстановка — не его дело.

**Инструмент раскрашен в Gruvbox.** Область, помеченная `class="tool"` — док, переключатели в верхней строке, легенда под машиной, — в обеих системных темах показана в палитре Gruvbox, а страница остаётся в палитре токенов. Читателю не нужно выяснять, приложение перед ним или инструмент, который за ним наблюдает.

Помечается именно область, а не виджет, и на то есть причина: часть того, что рисует инспектор, и есть предмет. Схему из примера `review` правят в `machjs-editor` и рисуют в `machjs-diagram`, но это документ, а не инструмент, — поэтому она стоит вне помеченной области и сохраняет цвета страницы, а конвейер, который её рецензирует, стоит в доке и раскрашен как инструмент.

Вся раскраска — блок custom properties и ничего больше: виджеты читают палитру как custom properties, а custom properties наследуются в теневое дерево.

## Как добавить пример

1. Каталог с `index.html` и `src/` рядом с `selection-rect`. Пути к файлам в разметке относительные — `./src/main.ts`, а не `/src/main.ts`.
2. Запись в `build.rollupOptions.input` в [`vite.config.ts`](vite.config.ts): сам Vite страницы не ищет.
3. Карточка в [`index.html`](index.html) — скопировать существующий `<li class="card">` и поправить текст и ссылки.
