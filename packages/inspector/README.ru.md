# machjs inspector

Инспектор конечных автоматов на [`@evgkch/machjs`](https://github.com/evgkch/machjs). Приложение вызывает `inspect(fsm)` одной строкой, а страница инспектора рисует три проекции этого автомата: текст правил, фигуру переходов и прогон. Проекции связаны общей подсветкой; когда названы обе половины перехода, он выполняется. Дамп схемы читается тем же инспектором, без работающей машины.

[**Открыть инспектор**](https://evgkch.github.io/machjs/inspector/)

## Установка

Страницы инспектора и [реле](#реле) запускаются из клона [`evgkch/machjs`](https://github.com/evgkch/machjs), где этот пакет лежит в `packages/inspector`. В отлаживаемое приложение ставится npm-пакет:

```sh
npm i -D @evgkch/machjs-inspector
```

В продакшен-сборку вызов `inspect` не берут:

```ts
if (import.meta.env.DEV) inspect(fsm, { name: "cart" });
```

Если виджеты входят в интерфейс страницы, пакет ставится обычной зависимостью.

Пакет поставляется только в формате ESM. Собственная зависимость одна: `lit`, база custom elements. В peer-зависимостях стоят `@evgkch/machjs >= 0.5.0` и `@evgkch/chanjs >= 1.0.0`; в сборку пакета они не входят, и копия `machjs` у приложения должна быть одна (см. [Ограничения](#ограничения)).

Точки входа:

| Точка входа    | Что в ней                                                                   |
| -------------- | --------------------------------------------------------------------------- |
| `.`            | `inspect`, `close`, `RELAY`. Ни DOM, ни стилей — подходит серверу и воркеру |
| `./ui`         | `overlay`, `mount`, виджеты, субъекты. Импорт подключает стили              |
| `./style.css`  | Стили светлого DOM: сетка `mount` и панель `overlay`                        |
| `./tokens.css` | Палитра и типографика; виджетам обязателен                                  |

## Способы работы

**Готовая страница.** В клоне `evgkch/machjs`, из его корня:

```sh
npm ci
npm run dev:inspector
```

Откроется инспектор: редактор схемы рядом с фигурой. Схему набирают в редакторе, читают из файла или берут из [готовых](#схемы); в файле лежит либо дамп `JSON.stringify(machine)`, либо текст на языке правил. Кнопка дампа выписывает набранное обратно в JSON.

**Работающий автомат.** [Реле](#реле) и страница наблюдения запускаются в клоне `evgkch/machjs`:

```sh
npm ci && npm run build -w @evgkch/machjs
npm run inspect -w @evgkch/machjs-inspector      # реле ws://localhost:8999 и страница наблюдения
```

В отлаживаемое приложение добавляется одна строка:

```ts
import { inspect } from "@evgkch/machjs-inspector";

const cart = inspect(new StateMachine(schema, start), { name: "cart" });
```

На странице появляется `cart`: его схема, текущее состояние и каждый новый переход. Машин может быть несколько, из одного процесса или из разных.

**На своей странице.** Инспектор встраивается в отлаживаемую страницу, без реле и без второй страницы: целиком через [`overlay`](#evgkchmachjs-inspectorui) или по одному виджету (см. [Виджеты](#виджеты)):

```ts
import { overlay } from "@evgkch/machjs-inspector/ui";
import "@evgkch/machjs-inspector/style.css";

const gone = overlay(cart);
// …
gone.close();
```

## `@evgkch/machjs-inspector`

Главную точку входа вызывает отлаживаемое приложение.

### `inspect`

```ts
function inspect<T extends AnyMachine>(fsm: T, opts?: Options): T;
```

`inspect` возвращает ту же машину, что получил: тот же объект с одним слушателем на шине.

| Поле опций     | Что делает                                                          |
| -------------- | -------------------------------------------------------------------- |
| `name?`        | Имя на странице инспектора. Без него — `machine N`                  |
| `description?` | Строка о том, для чего машина                                       |
| `history?`     | Рекордер `history(fsm)` из `@evgkch/machjs/debug` — включает отмотку |
| `carry?`       | Слать с шагами payload и контекст — то, что запишет JSON            |
| `url?`         | Адрес реле, когда оно не на этом хосте. По умолчанию `RELAY`        |
| `link?`        | Собственный канал вместо сокета; тогда `url` не используется        |

Машины одного процесса делят один сокет на адрес: соединение открывается на первом `inspect` и закрывается, когда отключается последняя машина. На `pagehide` за каждую машину отправляется `bye`.

### Отмотка

```ts
import { history } from "@evgkch/machjs/debug";

const past = history(cart);
inspect(cart, { name: "cart", history: past });
```

Отмотка из окна инспектора двигает машину в её процессе через переданный рекордер. Без `history` в опциях кнопки отмотки на странице не действуют.

### Что идёт по проводу

По проводу идут только имена. `JSON.stringify(machine)` записывает граф: схему без тел функций, но с именами функций. В каждом шаге записаны четыре типа перехода: `from`, `on`, `to` и `emit`. Контекст состояний и `payload` событий не покидают процесс приложения. С `carry: true` в шаг входят ещё payload, достигнутый контекст и payload выходного события, в той мере, в какой их запишет JSON; контексту с несериализуемым содержимым задаётся свой `toJSON`. Эти данные видны в консоли разработчика на странице инспектора.

| Сообщение | Кто шлёт   | Содержимое                                                |
| --------- | ---------- | ---------------------------------------------------------- |
| `hello`   | приложение | Всё о машине: имя, граф, состояние, прогон, возможности |
| `step`    | приложение | Один переход и текущее состояние машины                    |
| `bye`     | приложение | Машина перестала публиковаться                            |
| `hail`    | страница   | Запрос повторного `hello` от всех машин                       |
| `jump`    | страница   | Команда рекордеру: перейти к записи                      |

`hello` содержит состояние целиком, поэтому страница, открытая позже или пропустившая сообщения, шлёт `hail` и получает всё. Порядок доставки не важен, реле ничего не хранит.

### `close`

```ts
function close(): void;
```

`close` отправляет `bye` за все машины и закрывает сокеты. Node-скрипту этот вызов нужен: открытый сокет держит event loop, и без вызова процесс не завершится. Вкладке браузера он не нужен.

### Сигнатуры

```ts
function inspect<T extends AnyMachine>(fsm: T, opts?: Options): T;
function close(): void;
const RELAY = "ws://localhost:8999";

type Options = {
  name?: string;
  description?: string;
  history?: Past;
  carry?: boolean;
  url?: string;
  link?: Link;
};

/** Рекордер задан по форме: `History` из `machjs/debug` подходит. */
type Past = {
  readonly index: number;
  jump(index: number): boolean;
  readonly rx: { on(msg: "moved", hear: (index: number) => void): () => boolean };
};
```

## Реле

Реле работает WebSocket-сервером `scripts/relay.mjs`. К нему подключаются приложение с машинами и страница наблюдения; напрямую они не связаны.

```sh
npm run inspect            # реле и страница наблюдения вместе
npm run relay              # только реле
node scripts/relay.mjs 9001   # свой порт; иначе PORT, иначе 8999
```

Реле раздаёт каждое сообщение всем остальным клиентам; оно не разбирает сообщений и ничего не хранит. Если порт уже занят другим реле, второй экземпляр печатает одну строку и выходит.

## `@evgkch/machjs-inspector/ui`

Вторая точка входа содержит интерфейс инспектора для встраивания. Импорт модуля подключает `tokens.css`.

### `overlay`

```ts
function overlay(fsm: AnyMachine, options?: OverlayOptions): Overlaid;
```

`overlay` показывает работающую машину без реле и без второй страницы: фигура и прогон монтируются на этой же странице.

| Поле опций   | Что делает                                                    |
| ------------ | -------------------------------------------------------------- |
| `into?`      | Куда монтировать. Без него — плавающая панель поверх страницы |
| `title?`     | Подпись в шапке панели                                        |
| `history?`   | Рекордер — как у `inspect`, включает отмотку                  |
| `focus?`     | Общий фокус с другими виджетами страницы                      |

Плавающая панель перетаскивается за шапку и закрывается крестиком; `Overlaid.close()` делает то же из кода и снимает слушателя с машины.

### `mount`

```ts
function mount(host: HTMLElement, subject: Subject, options?: ViewOptions): Handle;
```

`mount` собирает в переданном элементе фигуру и прогон и связывает их: прогон листается с клавиатуры (`←`/`→`, `Home`/`End`, `Escape`), названное правило выполняется, панели располагаются рядом или столбиком по ширине хоста. В `ViewOptions` лежит одно поле `focus`.

```ts
type Handle = {
  readonly update: () => void; // перерисовать: субъект изменился
  readonly enroll: (s: Member) => void; // зарегистрировать ещё один виджет
  readonly fire: (id: RuleId) => void; // выполнить правило, если оно доступно
  readonly destroy: () => void; // отпустить слушателей и DOM
};

/** Виджет, зарегистрированный рядом с парой mount: перерисовывается вместе с ней. */
type Surface = { draw(start: string): void; dress(): void };
/** Виджет со свойством `wiring` проводится при регистрации сам. */
type Member = Surface & { wiring?: { subject: Subject; focus: Focus } };
```

`enroll` регистрирует виджет, например `<machjs-diagram>`, на тех же субъекте и фокусе; отдельная проводка странице не нужна.

### `ensemble`

```ts
function ensemble(subject: Subject, cast: Cast, options?: { focus?: Focus; start?: string }): Ensemble;

type Cast = { figure?: MachjsFigure; history?: MachjsHistory; diagram?: MachjsDiagram };
type Ensemble = {
  readonly focus: Focus;
  readonly start: string; // от какого состояния считаются ряды
  readonly draw: () => void; // перерисовать всех участников
  readonly dress: () => void; // обновить подсветку
  readonly fire: (id: RuleId) => void; // выполнить правило, если оно доступно
  readonly rewind: (step: number) => void; // подвинуть рекордер, сбросить выбор
  readonly forget: () => void; // сбросить выбор и указатель
  readonly enroll: (s: Member) => void;
  readonly destroy: () => void;
};
```

`ensemble` связывает виджеты без разметки. Виджеты независимы: каждый подписан на субъект и рисует себя. `ensemble` проводит участников на общие субъект и фокус и выполняет названное на любом из них правило. `mount` построен на `ensemble` и добавляет сетку, измерение и клавиатуру; страница со своей разметкой вызывает `ensemble` напрямую.

### Субъекты

Каждый виджет рисует с субъекта. Субъект держит граф, текущее состояние, прогон и перемотку:

```ts
function fromMachine(fsm: AnyMachine, opts?: { history?: Past }): Subject;
function fromText(graph: Graph, start: string): Text;
```

`fromMachine` читает работающую машину. Нажатие на правило отправляет событие, а какое из правил ячейки сработает, определяют условия в приложении.

`fromText` строит из дампа настоящую машину. Дамп хранит имена условий без кода, поэтому каждому правилу задаётся условие «названо ли именно оно», и срабатывает названное правило.

### Фокус

```ts
function newFocus(): Focus; // две машины: что выбрано и на что наведено; обе читает look()
```

Фокус собран из конечных автоматов на той же библиотеке. Общий `focus` на странице даёт общую подсветку.

## Виджеты

Панели инспектора публикуются как custom elements. Импорт любого из них регистрирует элемент:

```ts
import {
  MachjsFigure,
  MachjsHistory,
  MachjsEditor,
  MachjsDiagram,
  MachjsLegend,
} from "@evgkch/machjs-inspector/ui";
```

| Элемент           | Класс          | Что рисует                                             |
| ----------------- | -------------- | ------------------------------------------------------ |
| `<machjs-figure>`  | `MachjsFigure`  | Фигуру переходов: три блока вокруг двух осей           |
| `<machjs-history>` | `MachjsHistory` | Прогон: шаги по строкам состояний, отмотка кликом      |
| `<machjs-editor>`  | `MachjsEditor`  | Текст правил с подсветкой, гуттером и дополнением      |
| `<machjs-diagram>` | `MachjsDiagram` | Классическую диаграмму: состояния в строку, переходы дугами |
| `<machjs-legend>`  | `MachjsLegend`  | Строку капсул без рамки: `kind` — `states`, `in` или `out`  |
| `<machjs-desk>`    | `MachjsDesk`    | Пульт: меню переключателей и синхронизация остальных        |

Виджет настраивают свойством `wiring`; это объект JavaScript, а не атрибут. Рисует виджет в shadow root со своим стилем, и стили страницы внутрь не проникают. Снаружи проходит только палитра: токены записаны как custom properties и наследуются сквозь shadow. Поэтому `tokens.css` обязателен, а переопределение токена меняет и виджет.

Минимальная сборка фигуры с прогоном:

```ts
import {
  MachjsFigure,
  MachjsHistory,
  fromMachine,
  newFocus,
} from "@evgkch/machjs-inspector/ui";
import "@evgkch/machjs-inspector/tokens.css";

const subject = fromMachine(fsm);
const focus = newFocus();
const forget = () => {
  focus.choice.dispatch("drop");
  focus.pointer.dispatch("leave");
};
const start = subject.at;

const figure = new MachjsFigure();
figure.wiring = { subject, focus, forget };
host.append(figure);
figure.draw(start); // до draw ничего не нарисовано

const run = new MachjsHistory();
run.wiring = { subject, focus, rewind: (i) => subject.rewind?.(i) };
host.append(run);
run.show(subject.graph, start); // порядок строк
run.draw();
```

После смены графа `draw` зовут снова. После сдвига одного фокуса хватает `dress`. Названное правило выполняет не одиночный виджет, а связка: `mount` или `ensemble`.

`<machjs-diagram>` подключается так же: `wiring = { subject, focus, fire? }`, затем `draw(start)` или `handle.enroll(diagram)`. Поле `fire` берёт правило и сбрасывает выбор; `ensemble` передаёт свой `fire`, а без него виджет берёт правило сам.

Диаграмма рисует состояния ячейками в строку, а переходы дугами. Дуга налево идёт над строкой, дуга направо под ней, и цвет дуги повторяет цвет целевого состояния. Правила, различающиеся только условием, дают одну стрелку; правило с другим `emit` получает свою линию. Подпись собирается как `on · when / emit`, в той мере, в какой у правила есть условие и выход, поэтому три `down` из одного состояния различимы по именам условий. Подпись `on / emit` действует наравне со своей дугой, и на наведение, и на клик. Взятый машиной переход пробегает пунктиром по своей дуге на каждом шаге, чей бы он ни был.

| Действие читателя                                     | Что происходит                                                                                                                                     |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Наведение на дугу                                     | Правило этой дуги подсвечивается в фигуре и в тексте                                                                                               |
| Клик по дуге                                          | Выполняется доступное правило, выбор сбрасывается                                                                                                  |
| Клик по состоянию                                     | Состояние нажимается в общем выборе: на диаграмме остаются только его переходы, в фигуре — полоса его строки, в истории — пунктирные варианты шага |
| Клик по исходящему состоянию, затем по входящему      | Берётся переход между ними, наравне с кликом по дуге; то же состояние дважды даёт переход в себя                                                   |
| Наведение на входящее состояние при нажатом исходящем | В фигуре рисуются полосы кандидатов: строка источника, колонка цели, колонки их событий и строки выходов                                           |
| `Escape`                                              | Выбор сбрасывается, вместе с остальными виджетами                                                                                                  |

`<machjs-legend>` рисует строку капсул без рамки и без управления. Атрибут `kind` выбирает `states` (имена в цветах полос, текущее залито своим цветом, недостижимые зачёркнуты), `in` или `out`. На страницах инспектора над панелями стоят три такие строки, каждая под своим переключателем.

`<machjs-desk>` работает пультом: этот виджет управляет остальными. Внутри него стоит свой [`ensemble`](#ensemble), а в shadow root — меню с переключателем на каждый зарегистрированный виджет. Виджеты остаются в разметке страницы, а переключатель ставит и снимает у них `hidden`.

```ts
import { MachjsDesk, MachjsDiagram, fromMachine } from "@evgkch/machjs-inspector/ui";
import "@evgkch/machjs-inspector/tokens.css";

const desk = new MachjsDesk();
desk.wiring = { subject: fromMachine(fsm) };
bar.append(desk);

const diagram = new MachjsDiagram();
host.append(diagram);
desk.enroll(diagram); // проводка, отрисовка и переключатель
```

Переключатель получает имя тега без `machjs-`; нескольким виджетам одного тега имя задаётся вторым аргументом. Вызов `desk.seat(имя, { locked?, title? })` ставит переключатель без проводки, для панели, которую страница показывает и прячет сама; его состояние читается с `desk.panels`, машины панелей. В `desk.ensemble` лежит связка: `fire`, `rewind`, `forget` и `draw`.

`<machjs-editor>` собирается из `readSchema`: чтение даёт правила с номером строки, а `show` принимает их вместе с цветами состояний и результатом проверок.

```ts
function readSchema(text: string, keep?: string): Read;

type Read =
  | { ok: true; graph: Graph; start: string; rules: readonly Written[] }
  | { ok: false; say: string; line: number | null };
```

```ts
import {
  MachjsEditor,
  flaws,
  newFocus,
  palette,
  readSchema,
} from "@evgkch/machjs-inspector/ui";
import "@evgkch/machjs-inspector/tokens.css";

const editor = new MachjsEditor();
// За текстом нет машины: выполнять нечего, текущего состояния нет.
editor.wiring = {
  focus: newFocus(),
  onEdit: () => paint(),
  fires: () => false,
  here: () => "",
  fire: () => {},
};
host.append(editor);

let start = "";

function paint(): void {
  const read = readSchema(editor.text(), start);
  // Редактор показывает сообщение и его строку на нижней полосе.
  if (!read.ok) return editor.blame(read.say, read.line);
  start = read.start;
  editor.blame(null, null);
  editor.show(read.rules, palette(read.graph, start), flaws(read.graph, start));
}

editor.set("FROM locked ON coin TO open\nFROM open ON pass TO locked\n");
paint();
```

`readSchema` читает оба вида текста, язык правил и JSON-дамп, и не бросает исключений. Результат разбора различается по полю `ok`. При `ok: true` возвращаются `graph`, `start` и `rules`; при `ok: false` возвращаются сообщение `say` и строка `line`, к которой оно относится. У дампа строк нет, и там `line` равно `null`. Второй аргумент задаёт состояние, с которого продолжается прогон: оно сохраняется, пока такое состояние есть в графе, иначе берётся первое состояние графа.

| Поле `wiring` | Что делает                                                                          |
| ------------- | ----------------------------------------------------------------------------------- |
| `onEdit`      | Вызывается на каждое нажатие клавиши; страница инспектора читает текст через 300 мс |
| `fires`       | Возвращает, доступно ли правило из текущего состояния                               |
| `here`        | Возвращает имя текущего состояния                                                   |
| `fire`        | Выполняет правило                                                                   |

С `subject` и общим с фигурой `focus` клик по метке в гуттере выполняет правило своей строки. Оттуда же экспортируются типы `Read`, `Shown`, `Written`, `Row`, `Lane` и `Flaws`.

## Схемы

В `schemas/` лежат девять готовых файлов. Шесть файлов `the-inspectors-*` содержат схемы машин самого инспектора, выписанные из его исходников командой `npm run dump`. Три файла написаны вручную: `selection-rectangle`, `upload-with-retry` и `a-schema-with-problems`. В последнем видно, как выглядят мёртвые правила и недостижимые состояния.

Файл читается в двух видах: JSON-дамп и язык правил библиотеки:

```text
FROM locked ON coin WHEN underCap TO locked WITH addCoin
FROM locked ON coin               TO open   WITH reset   EMIT opened
FROM open   ON pass               TO locked
```

`FROM`, `ON` и `TO` обязательны, порядок слов фиксирован, а комментарий начинается с `#` или `//` и идёт до конца строки. После круга «текст → схема → дамп» получается та же схема, а не эквивалентная.

Такой же текст возвращает `toRules(schema)` из `@evgkch/machjs/formatters`: его выводят в консоль и вставляют в редактор.

## Ограничения

- **Копия `@evgkch/machjs` у приложения должна быть одна.** Переходы публикуются по символу `TRANSITION`, а у второй копии библиотеки символ свой, и слушатель `inspect` не срабатывает. При сборке из нескольких бандлов помогает `resolve.dedupe` у Vite.
- **Node-скрипту нужен `close()`.** Открытый сокет держит event loop; без вызова процесс не завершится.
- **Отмотка требует переданного рекордера.** Без `history` в опциях `inspect` кнопки отмотки не действуют.
- **По проводу идут только имена, если не задан `carry`.** Условия дампа не выполняются: страница наблюдения отправляет событие, а какое правило сработает, определяют условия в процессе приложения. Без `carry: true` контекст и `payload` не покидают приложение.
- **Виджетам нужен `tokens.css`.** Палитра проходит в shadow root через custom properties; без токенов виджет остаётся без цветов.
