## Установка

```sh
npm ci
npm run build
```

Сборка идёт по трём workspace в таком порядке: `packages/core`, `packages/inspector`, `examples`. Каждый следующий импортирует предыдущий по workspace-ссылке, а ссылка ведёт на результат сборки — `dist` у библиотеки, `dist-lib` у инспектора. Поэтому в свежем клоне и после правки публичных типов пакета `npm run typecheck` и `npm test` запускают после сборки.

## Скрипты

| Команда                 | Что делает                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------- |
| `npm run build`         | Три workspace по порядку                                                            |
| `npm run typecheck`     | `tsc --noEmit` в каждом из них                                                      |
| `npm test`              | Три набора тестов, описанных ниже                                                   |
| `npm run format`        | Prettier по репозиторию; `*.md` размечены вручную и исключены                       |
| `npm run dev:examples`  | Собирает библиотеку и пакет инспектора, затем поднимает примеры                     |
| `npm run dev:inspector` | Собирает библиотеку, затем поднимает страницы инспектора                            |
| `npm run site`          | `site/` из двух сборок: примеры в `/`, инспектор в `/inspector/`                    |

По одному workspace: `npm run <скрипт> -w <имя>`, например `npm test -w @evgkch/machjs`.

Реле — WebSocket-сервер для автомата, работающего в другом процессе, — запускается командой `npm run inspect -w @evgkch/machjs-inspector`. Что через него передаётся, написано в [README инспектора](packages/inspector/README.ru.md#реле).

## Тесты

| Набор                                   | Что проверяет                                                                     |
| --------------------------------------- | ----------------------------------------------------------------------------------- |
| `packages/core/test/*.spec.ts`          | Ядро: dispatch, вердикты, вложенные вызовы, анализ, форматы                        |
| `packages/inspector/scripts/matrix.mjs` | Каждое действие над одним виджетом и его отражение в трёх остальных                |
| `examples/scripts/pages.mjs`            | Каждую страницу примера в DOM: автомат прогоняется, виджеты пересчитываются        |

Первый набор — jest. Последние два поднимают настоящий DOM (happy-dom) над исходниками через Vite и завершаются с кодом 1 на первом расхождении: это интеграционные тесты библиотеки, и проверяют они workspace, а не опубликованные пакеты.

В `packages/inspector/schemas/` лежат дампы собственных автоматов инспектора; их пишет `npm run build -w @evgkch/machjs-inspector`. Если дамп не закоммичен, проверка в CI завершается ошибкой.

## Соглашения

- Сообщение коммита — одна строка об изменении. Коммит версии: `0.5.0 — что изменилось`. Без трейлеров.
- Prettier форматирует код. Проза из форматирования исключена: таблицы, переносы и ширина линеек размечены вручную и по смыслу.
- В комментарии — ограничение или довод, одно-три предложения.
- В `peerDependencies` инспектора указана самая старая версия библиотеки, которую его адаптеры читают верно. Когда инспектор следует за изменением публичного API библиотеки, диапазон сдвигают.

## Выпуск

Публикуются два пакета: `@evgkch/machjs` из `packages/core` и `@evgkch/machjs-inspector` из `packages/inspector`. В теге записаны имя пакета и версия; [`publish.yml`](.github/workflows/publish.yml) собирает и прогоняет репозиторий, сверяет тег с манифестом и публикует один этот пакет с provenance. Токен в репозитории не хранится.

1. Проставить версию в `package.json` пакета.
2. Закоммитить: `0.5.0 — …`.
3. Поставить тег и запушить его.

```sh
git tag machjs@0.5.0 && git push origin machjs@0.5.0            # библиотека
git tag machjs-inspector@0.0.9 && git push origin machjs-inspector@0.0.9
```

Trusted publishing настраивается один раз на пакет на npmjs.com, до первого тега: _Settings → Trusted publisher → GitHub Actions_, репозиторий `evgkch/machjs`, workflow `publish.yml`.

## История до переезда

Инспектор, примеры и палитра были отдельными репозиториями, пока `git subtree add` не внёс их сюда, поэтому каждый коммит, которым они сделаны, достижим из этого репозитория. На subtree-слиянии останавливаются `git log --follow` и `git blame`. Чтобы прочесть историю файла до переезда, назовите путь и запросите полную историю:

```sh
git log --full-history -- packages/inspector/src/widgets/figure/figure.ts
git log --full-history -- examples/selection-rect/src/main.ts
```
